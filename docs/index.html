📦 Tally Pack

Muse places the order. Tally proves it was packed right.

A fixed camera watches the packing desk. SAM 3.1 tracks every item, a deterministic ledger proves the box matches the order, and Muse Glimmer 30B investigates only when the evidence doesn't add up. It never gives a false clearance.

How it works


Perception you can audit: models propose, plain code decides.




MUSE GLIMMER 30B
Order → contract
“2 maggi and a coke” becomes validated SKU counts. Unknown items are asked about, never guessed.


SAM 3.1
Track every item
Text-prompted video segmentation by category (“packet”, “soda can”), one stable ID per item.


PLAIN CODE · 0 MODEL CALLS
Ledger + verifier
C1 order · C2 conservation · C3 continuity · C4 ID switch · C5 ambiguous identity.


MUSE GLIMMER 30B
Investigator
Sees the violation and crops of the items, then picks one repair or escalates to a human.


VERIFIER GATE
Keep only proven fixes
A repair is accepted only if issues drop and no new ones appear. Otherwise a human signs off.




Glimmer can never clear a box. Only the verifier issues PASS or FAIL, and only on consistent evidence.







Results


PackBench: 30 fixed-camera packing clips (clean, missing, extra, wrong item, occlusion, twins), each run as rendered and with an injected tracker ID switch.
